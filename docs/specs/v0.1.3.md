# v0.1.3 追加・変更仕様

ノート PC などの小さい画面でもデスクトップ版を操作できるように、最小ウィンドウサイズと画面サイズに応じた表示を改善する。あわせて Windows の署名付きビルドと成果物管理を改善する。モバイル版は日記・タイマー・パスワード生成を Expo SDK 58 の新しい `apps/mobile/` へ移植する。
変更のない機能は [v0.1.0 現行仕様](v0.1.0.md) と [v0.1.2 追加・変更仕様](v0.1.2.md) を引き継ぐ。仕様書はバージョンごとに集約し、プラットフォーム固有の変更・制約は対象を明記する。

## 対象プラットフォーム

- ウィンドウサイズと表示の変更は、デスクトップ版の Windows・Linux・macOS を対象とする。
- デスクトップ版の日記・タイマー・パスワード生成の機能と保存形式は従来の仕様を引き継ぐ。
- モバイル版の Android・iOS は、下記の Expo 移植と各機能・保存形式・署名付きビルドの変更を対象とする。
- ウェブ版の UI とバージョンは本変更の対象外とする。

## デスクトップ：ウィンドウサイズ

- 最小ウィンドウサイズを、従来の1200×800から **800×600 論理ピクセル**へ変更する。
- サイズはコンテンツ領域を指し、タイトルバー・ウィンドウ枠を含めない。OS の表示倍率を適用した物理ピクセル数とは区別する。
- 通常起動時の既定サイズは、従来どおり1280×860とする。
- 起動先モニターの作業領域に既定サイズが収まらない場合は、表示倍率・タイトルバー・ウィンドウ枠を考慮して縮小する。作業領域からはタスクバーなどの占有領域を除く。
- 縮小する場合は、作業領域内で中央に配置する。作業領域に収まる場合は既定サイズを維持する。
- 自動調整でも800×600の最小サイズは維持する。作業領域が最小サイズとウィンドウ枠を収容できない環境では、ウィンドウ全体の表示を保証しない。
- フルスクリーン・最大化状態は起動時のサイズ調整の対象外とし、通常ウィンドウでの操作を可能にする。

## デスクトップ：ウィンドウサイズに応じた表示

- 起動後の縮小・拡大にも追従し、幅と高さに応じて余白・列幅・見出し・タイマーの大きさを調整する。
- 幅だけでなく、高さだけを縮めた場合にも操作に必要な領域を確保する。
- 800×600以上では、ホーム・日記・タイマー・パスワード生成をページ全体のスクロールなしで操作できるようにする。
- 日記本文と、長いファイル名・エラーを含む終了音設定の内部スクロールは許容する。

| 画面 | 最小サイズでも利用できる表示・操作 |
| --- | --- |
| 共通・ホーム | アプリの切り替え、ホームからの起動、アプリ画面を閉じる操作 |
| 日記 | 日付移動、カレンダー、本文編集、文字数・保存状態、保存、未保存変更の確認 |
| タイマー | 残り時間・進捗、時間入力、開始・一時停止・再開・リセット、終了音設定の展開と操作 |
| パスワード生成 | 文字種・文字数・間違えやすい文字の除外、生成、結果表示、コピー、警告・エラー |

- 表示の調整によって日記の入力内容やタイマーの計時状態などが失われないようにする。
- エラー・警告・確認ダイアログの表示時にも、操作ボタンが重ならず利用できるようにする。

## デスクトップ：受け入れ条件

- ネイティブアプリで800×600まで縮小でき、それ未満への縮小が制限される。
- 800×600、1000×600、1280×600、1024×768、既定の1280×860で、各画面の表示・操作を確認する。
- 起動中に幅・高さをそれぞれ縮小・拡大しても、操作部品が見切れず、入力内容・計時状態を維持する。
- 小さいモニターや表示倍率を変更した環境でも、最小サイズとウィンドウ枠が収まる作業領域で初期配置を確認する。
- 日記の長文入力・保存失敗・未保存変更の確認、タイマーの入力エラー・終了音設定の展開・長いファイル名、パスワードの短い文字数の警告・文字種未選択を含めて確認する。
- Windows では、対象ユーザーの GUI ログオン後にビルドが進み、署名・ハッシュ・バージョンを検証した NSIS・MSI・署名レポートが `dist/windows/v0.1.3/` に揃う。
- Windows のビルド失敗・中断・通信断後の回復時に、その実行の停止と後片付け、失敗ログの回収、既存成果物の保持を確認する。
- インストールしたアプリで `v0.1.3` の表示、日記の保存・再読込、タイマー完了時の音声を確認する。

Windows のタスクスケジューラ方式は仮実装であり、ログ処理の修正と成果物の集約・バージョン検証を含めた通し実行は実機未検証である。検証状況と実行手順は [Windows の署名・配布の開発文書](../development/dist/windows/sign.md) を参照する。

## モバイル：Expo 移植

### 移植方針

- 旧 React Native CLI 実装は `apps/mobile-old/` に隔離する。workspace と通常のチェック・ビルドの対象に含めない。
- Expo SDK 58 / React Native 0.88 / React 19.3 を使う。デスクトップ・ウェブの React 19.2.3 は維持し、全 workspace に同じ React を強制する override は撤去する。
- 新プロジェクトのネイティブ設定に従い、Android の minSdk は 24（Android 7.0）、iOS の Deployment Target は 16.4 とする。
- 画面遷移は Expo Router のホーム・Diary・Timer・Password タブに変更する。画面の実装は `src/apps/`、経路定義は `src/app/` に分ける。
- 自作 TurboModule・Codegen Spec・Objective-C++ 接続処理は移植しない。現在の機能はすべて Expo 公式モジュールで実装する。
- 旧保存形式・保存場所との互換性や自動データ移行は提供しない。pre-release の仕様変更として新しい保存領域を使用する。
- Android の application ID `jp.co.kupacllc.prelis`、iOS の bundle ID `jp.co.kupac.prelis` と既存の署名鍵・証明書を維持する。内部管理用の `package.json`・アプリ内表示・仕様書のバージョンは 0.1.3 とする。

### 日記

- 日付移動、月カレンダー、日本語・絵文字を含む本文、文字数、明示的な保存、保存状態・読込／保存失敗の表示を提供する。
- `expo-sqlite/kv-store` の `diary:YYYY-MM-DD` に本文を保存する。独自のファイル置換処理は使用しない。
- タブを切り替えても編集中の本文を保持する。従来のタブ離脱時の破棄確認は行わない。別の日付へ移動する際は未保存内容の破棄を確認する。
- 保存失敗時には入力内容を保持する。アプリ終了後の未保存内容の復元は保証しない。

### タイマー

- 1〜180 分、開始・一時停止・再開・リセット、残り時間と進捗を提供する。
- 状態をルートの TimerProvider に置き、タブを切り替えても計時する。アプリ終了時はリセットする。
- バックグラウンド中の正確な終了音は保証しない。復帰時に期限との差を再計算する。バックグラウンド再生・録音・通知サービスは追加しない。
- MP3・WAV を `expo-document-picker` で選択し、キャッシュにコピーされた実ファイルを検証する。空ファイルと 10 MiB 超過を拒否する。選択処理が検証前に一時コピーすることは許容する。
- 音声本体は Expo FileSystem の Documents 配下 `timer/sounds/<UUID>.mp3|wav` にコピーする。OS が消去できるキャッシュを永続保存先にしない。
- 音声一覧・選択状態は SQLite の `timer:sounds` に保存する。保存済みの不正データは読込エラーとし、空の一覧で上書きしない。
- 取込み後の一覧保存失敗時は追加ファイルを削除する。削除時は一覧保存の成功後に音声本体を削除し、保存失敗で既存の音声を失わないようにする。選択画面のキャンセルでは一覧を変更しない。
- `expo-audio` で試聴は 1 回、終了音はループ再生し、リセット・音声変更時に停止する。OS による割込み・接続機器の切断は Expo の再生動作に従う。
- マイク・録音の権限は要求しない。

### パスワード生成

- 大文字・小文字・数字・記号、4・8・12・16 文字、選択した文字種の包含、短いパスワードの警告、結果のコピーを提供する。
- 生成ロジックは `@prelis/core` を使用し、乱数源は `expo-crypto.getRandomBytesAsync` とする。暗号学的乱数を `Math.random` に置き換えない。
- コピーは `expo-clipboard` を使用し、Android では sensitive として設定する。設定・結果は同一起動中のタブ切替で保持し、アプリ終了後に復元するための永続化は行わない。

### ビルド・署名

- 旧版の公開バージョン 1.0・ビルド番号 1 に続く更新として、ストア向けの公開バージョンは Android・iOS ともに 1.0.1 とする。Android の `versionCode`、iOS の `buildNumber` はともに 2 とする。
- Expo の `version` はストア向けの 1.0.1 とし、Gradle の `versionName`、iOS の `CFBundleShortVersionString`・`MARKETING_VERSION` と一致させる。`versionCode` と `CFBundleVersion`・`CURRENT_PROJECT_VERSION` も Expo 設定と一致させる。
- 今後の更新ではストアの提出履歴に続く公開バージョン・ビルド番号を使用する。ストア管理画面に今回の基準より新しい提出がある場合は、その値に続く番号へ更新する。
- 開発サーバー・端末起動・JS バンドルは Expo CLI を使用する。Expo アカウント登録・EAS の利用は行わない。
- `ios/`・`android/` は Git 管理する。通常のビルドで Prebuild による再生成は行わず、署名付き配布は既存の Gradle・Xcode ワークフローを維持する。
- Android は Play 用 AAB と直接配布用 APK の鍵を分ける。デバッグ鍵の standalone APK と配布用 release は別の build type とする。
- iOS は Mac への同期、CocoaPods、Xcode の archive・export、既存証明書・プロファイルによる署名、成果物検証を維持する。
- 鍵・証明書・パスワードを Expo に登録・アップロードしない。

### 受け入れ条件

- 型チェック・Expo lint・Jest と、Android・iOS の JS／画像バンドル生成が成功する。
- 日記の保存・再読込、日本語・絵文字、タブ切替時の下書き保持、日付変更時の確認を検証する。
- パスワードの各文字種とコピーを検証する。
- 音声のキャンセル・空ファイル・10 MiB 境界と超過・一覧保存失敗時の清掃・削除保存失敗時の既存ファイル保持を検証する。
- タブをまたぐタイマーの継続、完了時のループ再生要求、リセットによる停止、音声選択の永続化を検証する。
- 新しいネイティブプロジェクトで実ビルドを行い、従来の署名設定を引き継いだ成果物を確認する。

実施した検証と未確認事項は [開発文書](../development/mobile-native.md) に記録する。

# v0.1.4 追加・変更仕様

変更のない機能は [v0.1.3](v0.1.3.md) と同書が参照する仕様を引き継ぐ。

## 対象とバージョン

- デスクトップ（Linux・Windows・macOS）とモバイル（Android・iOS）を `0.1.4` に更新する。ウェブ版は対象外。
- 各アプリの npm パッケージ・lockfile・画面表示・ネイティブ設定を揃える。モバイルのビルド番号は Android・iOS ともに `3` とする。

## プライバシーポリシー

- URL は `https://prelis.prj.kupac.co.jp/privacy` とする。
- デスクトップは、全機能から利用できるサイドバー下部に「プライバシーポリシー」リンクを表示する。既存の Tauri Opener で既定の外部ブラウザーを開く。
- モバイルはホーム画面に同じラベルのリンクを表示する。既存の Expo Linking で既定の外部ブラウザーを開く。タッチ領域の高さは44以上とする。
- 支援技術へリンクとして伝え、ブラウザー起動失敗時には画面上にエラーを表示する。デスクトップではキーボードのフォーカスを視認できるようにする。
- ポリシーの閲覧にはインターネット接続が必要。日記・タイマー・パスワード生成の処理と保存方法は変更しない。

## 検証と審査資料

- デスクトップの Vite では React・React DOM の解決先をデスクトップ側に統一する。モバイル用にルートへ配置された別バージョンを共有依存が取り込み、起動時に空画面となる問題を防ぐ。
- プライバシーポリシー追加時は Linux のネイティブアプリで動作確認し、他のプラットフォームのビルド・実機確認は実施しない。後述する macOS E2E の導入は別の検証工程とする。
- iOS 審査メモと返信の英文テンプレートを `dist/app-store-ios/app-review-notes.txt` と `app-review-reply.txt` に保存する。
- macOS の同様の情報追加要求に備え、Mac 版の英文審査メモ・返信・実機動画の手順・確認用の合成 WAV を `dist/app-store-mac/` に保存する。Mac の Sidebar 操作・ファイル保存・Tauri 構成に合わせ、iOS のビルド番号や実機検証結果を流用しない。資料準備では Mac の追加ビルド・実機確認・送信は実施しない。
- 動画・実機テスト・提出ビルドなど未確定の値はプレースホルダーにし、実施済みと記載しない。再提出前に実際の結果で置換する。

## ネイティブ E2E の導入（macOS から開始）

- `tests/e2e/platforms/<OS>/` に共通の起動・待機処理、`tests/e2e/domains/<機能名>/<OS>/` に操作シナリオと期待結果を配置する。機能固有の画面ヘルパーは同じ機能内に置く。
- macOS は独立した XCTest / XCUIAutomation ターゲットで、明示された既存の `.app` をパス指定で起動する。アプリ本体のビルド・署名変更・インストールは行わない。
- 最初の対象は日記の保存・アプリ終了・再起動後の内容一致とする。翌日から14日以内の空の日付だけを使い、既存の日記を上書きしない。テスト入力は終了時に消去して保存する。クラッシュなどで後片付けができない場合は結果を使って復旧する。
- 対象のパス・Bundle ID・バージョン・ビルド番号・アプリ全体と実行ファイルの SHA-256、固定入力・テストソースの SHA-256、OS・Xcode 情報を記録する。
- テスト結果・ログ・スクリーンショット・`.xcresult` を実行ごとに `artifacts/e2e/` へ保存する。初回の UI 自動操作認証に起因する失敗はアプリ機能の失敗と区別する。
- `--record` 指定時は Xcode 標準の UI テスト画面記録を成功時にも保持し、動画と SHA-256 を保存する。テストの成否と動画取得の成否は独立して記録する。
- Mac ではローカル実行し、Ubuntu では既存 SSH 設定でテストコードだけを転送して同じテストを実行する。結果は Ubuntu に回収する。Mutagen の同期・セッション変更は E2E 実行に含めない。
- iOS 実機・他機能のシナリオ・実際の提出対象に対する審査用の全機能の検証は、macOS の最小 E2E が成立した後に追加する。

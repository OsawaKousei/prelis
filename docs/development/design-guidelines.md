# Prelis デザインガイドライン

デスクトップ・モバイル・ウェブの視覚・操作デザインに適用する。
画面構成と操作方法は各プラットフォームに合わせる。

## 基本方針

**CLEAR / LIGHT / SPEED — 明るく、透明で、軽快な体験**を目指す。
整理された情報、精密な文字と線、余白、素早い反応によって品質を表現する。

- 明るさ：白・アイスブルー・淡いブルーグレーを基調にする。
- 透明感：半透明の表現は、前後関係や情報階層を示す場所に限定する。
- 余白：要素を密集させず、情報のまとまりを明確にする。
- 精密さ：文字・線・アイコンの形と配置を揃える。
- 速度：操作へ素早く反応し、その後の動きを滑らかにつなぐ。
- 最小限：色・線・装飾・動きには明確な役割を持たせる。

## 色

| 役割 | 基準 |
| --- | --- |
| ブランド・主要操作 | ライトブルー～シアン。リンク、選択、フォーカスなどに使う |
| 背景 | 白・青みのある白。補助領域には淡いブルーグレーを使う |
| 表面・境界 | 白と透明感、淡いブルーグレーの細い線を使う |
| 本文 | 濃いブルーグレー。補足には中間のブルーグレーを使う |
| 警告・エラー・削除 | 赤。装飾や通常の強調には使わない |
| 分類・補助情報 | アンバー・オレンジ・マゼンタ・バイオレットを限定的に使う |

- 主要色は白やニュートラルカラーの中に控えめに配置し、強い色で広い面を埋めない。
- 色数を抑え、同じ意味には同じ色を使う。純黒は原則避ける。
- グラデーションは白→アイスブルー、アイスブルー→淡いシアン、クリアブルー→淡い紫など、低彩度で滑らかにする。
- 状態は色だけで示さず、ラベル・アイコン・線・形などを併用する。

## 情報階層とレイアウト

視覚的な優先順位は、主要メッセージ → 主要操作 → 閲覧中の内容 → 補助操作 → 補足情報 → 装飾 → 背景とする。

- 広い余白と文字の強弱で情報を区切り、大きなまとまりを明確にする。
- 全要素を箱で囲まず、小さなカードの大量配置、過剰な枠線、強い背景色による分割を避ける。
- 重要な情報を先に示し、補足・詳細はアコーディオン、タブ、詳細画面などで段階的に提示する。
- 情報を隠す場合は、必要な内容へ迷わず到達できる構成にする。
- 長いページは情報密度と余白に変化をつけ、単調さと視覚的な疲労を抑える。
- デスクトップでは対応画面内に優先順位を保って再配置し、設定展開時もページ全体のスクロールなしで操作できるようにする。長文入力欄などの内部スクロールは許容する。
- モバイル・ウェブの小画面では、縦スクロールとタッチ操作に合わせて再配置する。

## 表面・線・画像

- 表面は薄く軽い印象にし、半透明、微細な境界線、軽いぼかし、淡いハイライト、控えめな影を必要に応じて使う。
- 境界線は細くし、入力欄、選択状態、情報同士の関係を示すために使う。
- 画像は明るい自然光、空間、透明素材、柔らかな光の反射、抽象的な流線などを基本にする。
- 背景の光・粒子・グリッド・形状は低コントラスト・低彩度にし、本文や主要操作より弱くする。
- 透明な表面でも、背景に対する文字・操作要素のコントラストを確保する。

## 文字と文章

- 日本語と欧文の両方が読みやすく、字形と数字が明快なサンセリフを使う。
- 見出しは大きく、本文は読みやすくする。細すぎるウェイトを避け、サイズ・太さ・配置で階層を作る。
- 中心メッセージ、見出し、本文、ラベル、数値の役割を区別する。
- 短い英字ラベルには必要に応じて字間を設け、数値の比較には等幅数字を使う。
- 一文を短くし、見出しだけでも内容を理解できるようにする。
- 同じ意味には同じ用語を使い、不要な専門語や装飾的な英語を避ける。
- 操作ラベルは、実行内容が分かる具体的な動詞で書く。

## ボタンとアイコン

- 主要・補助・第三の操作の優先順位を明確にし、主要ボタンを同一画面に大量配置しない。
- 主要ボタンは淡いブルー、軽い境界やハイライトを基調にし、十分なサイズとコントラストを確保する。
- アイコンは単純・幾何学的・細い線を基本にし、線幅・角丸・サイズ感を揃える。
- 複数のアイコンセットを混在させず、共通アイコンは [packages/icons/assets](../../packages/icons/assets/) の透過 PNG を正本とする。
- ブランドマークには `brand.png` を使い、各アプリで共通の画像を使用する。
- 重要な操作にはアイコンとテキストラベルを併用する。

## 操作状態と動き

操作への反応は素早く、その後は滑らかにつなぐ（**Snap + Glide**）。

| 対象 | 時間の目安 |
| --- | --- |
| ホバー | 100～150 ms |
| ボタン・トグル | 150～200 ms |
| 小さな状態遷移 | 200～300 ms |
| セクションの表示・切り替え | 300～600 ms |
| 大きな画面遷移 | 500～800 ms |

- ホバー・フォーカス・押下・読み込み・成功・エラーを明確にし、操作結果を視覚的に返す。
- 開閉前後で操作対象を不必要に移動させず、フォーカス表示をラベルや内容に重ねない。
- 出現は明確に、移動は滑らかにする。フェード、スライド、微小な拡縮、線やマスクの表示などを使う。
- 視差、光の軌跡、ぼかしの変化は補助表現に限定し、長い演出で操作を待たせない。
- バウンド、弾性やばねの強い動き、激しい回転、大きなズーム、常時動く背景、過剰なスクロール演出を避ける。

## アクセシビリティ

可読性と操作性を優先する。

- 文字・操作要素に十分なコントラストとサイズを確保する。
- キーボード操作と明確なフォーカス表示を提供する。
- クリック・タッチ領域を十分に確保する。
- 色以外でも状態を判別できるようにする。
- フォームには明確なラベル、画像には役割に応じた代替テキストを付ける。
- 対応画面サイズで操作できることと、動きを減らす設定への配慮を確認する。

## 避ける表現

- 暗いサイバーパンク調、黒とネオンの多用、重厚な工業表現。
- 意味のない未来的記号、六角形、HUD 風装飾、英数字、ノイズ、グリッチ。
- 過剰な発光、強い背景ぼかし、厚い影や立体ボタン、光沢の強いガラス表現。
- 高彩度・虹色のグラデーション、多すぎるアクセント色やガラス風カード。
- 内容より目立つ背景・装飾・アニメーション。

## 確認項目

- 明るさ・余白・透明感があり、情報の優先順位と主要操作が明確か。
- 主要色を使いすぎず、赤を警告・エラー・削除に限定しているか。
- 文字が読みやすく、色だけに頼らず状態を把握できるか。
- 操作に素早く反応し、意味のある動きだけを使っているか。
- 対応画面サイズで操作でき、キーボード・タッチ・動きを減らす設定に配慮しているか。
- 不要な要素を削り、装飾より内容を優先しているか。
